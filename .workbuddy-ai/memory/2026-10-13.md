## 踩到的坑（重要）

1. **`std.fs.path.resolve` 在 Zig 0.17 是纯词法的，不查 CWD**（0.17 里它 = `resolveAlloc`）。
   `resolve(&.{"."})` 原样返回 `"."`。要复刻 Go 的 `filepath.Abs` 必须自己
   `std.Io.Dir.cwd().realPathFileAlloc(rt.io(), ".", alloc)` 拿 CWD 再 join。
2. **pan123 的并发上传照抄 itvsh 的既有模式**（`itvsh.zig:1004-1224`）：
   每 worker **一个独立 `httpclient.Client`**（因为 `Client.send` 内部有一把锁，
   共用一个 client 等于没并发）、**一个独立 arena**（arena 非线程安全）、
   **一块独立 buffer**、原子 `next.fetchAdd` 领号、`cancel` 标志 + `first_err`。
   403 换 URL 用 mutex 保证整批只换一次（对齐 Go 的 singleflight）。
   顺带修了「小文件也分配 16 MiB buffer」的浪费（改按 `min(chunk_size, size)`）。
3. Go 的 `mime.TypeByExtension` **平台相关**（Linux 读 `/etc/mime.types`），
   逐字复刻不可能，只能做固定表。已写进 `util/mime.zig` 头注。

## 2026-10-13 下午的坑（新增方法论）

- **Zig 是惰性分析**：`vtable` 里引用一个不存在的函数，`zig test` 全绿、二进制
  也不报错，直到运行时才 panic。改完 vtable 必须额外跑一次 `zig build-exe`
  （本轮为查这个专门加了一步）。
- **`var self: T = undefined` 后只赋了部分字段**，下面 `switch` 那个枚举字段直接
  "switch on corrupt value" panic。测试里构造半成品结构体也要显式给默认值。

  被误插进 `streamUpload` 尾部，因为两段收尾代码逐字相同）。定位要靠行号 +
  上下文，不能只匹配 `self.isFamily(),\n false,\n );`。

## 2026-10-13 晚 — 真机部署（光猫 192.168.1.1，Zig 版 /tmp/olz，端口 15344）

### 传输：大文件必须走 SCP，SFTP 会断
- **SFTP 传 1.1MB 二进制必 EOFError**（dropbear 会话被杀）；传 10KB 的 config.json
  完全正常。用户用 WinSCP 选 **SCP 协议**一次成功。
- 我自写的 paramiko SCP（`scp -t` 模式）也卡住 —— 结论：**大文件让用户用
  WinSCP SCP 传**，别自己折腾分块/断点续传。
- ⚠️ `remote.py --put` 的路径：`abs_remote('tmp/olz/x')` → `/tmp/olz/x`（设备根下，
  tmpfs，正确）。**必须传相对路径或配 `MSYS2_ARG_CONV_EXCL='*'` 后的绝对路径**；
  本机实测绝对路径 `/tmp/olz/x` 是对的（probe 验证过）。

### remote.py 的 CLI 有坑
- `cmd = " ".join(rest)` **不加引号**，所以 `sh -c 'a; b; c'` 会被拆散，只有第一条
  进 sh。**要把整串命令作为单个 argv 传**：`remote.py host port 'a; b; c'`。

### 设备 busybox 的阉割
- `chmod` **完全失效**（755 / 0755 / u+x / a+rx / rwxr-xr-x 全报 usage，overlay 所致）。
  → 改用 **SFTP 协议 chmod**：`sftp.chmod(path, 0o755)` 有效。
- 无 `pkill`、`stat`、`install`、`printf %s` 有坑、`base64` 不在 PATH（busybox 里有
  但没单独链接）、ash **不支持 `for ... do`**、`umask` 改不动（恒 0000）。
- `/tmp` 是 tmpfs（24MB, mode=777）—— 临时部署的正解；`/root/tmp` 是持久化，别往那传。

### 部署流程（可复用）
1. 用户 WinSCP SCP 传 `dist/openlist-aarch64` → `/tmp/olz/openlist`
2. `import_go_config.py <go备份> <out.json>` 转配置；改 `scheme.http_port`、`zig.sign_all`、
   `zig.ca_bundle=/etc/ssl/certs/ca-certificates.crt`、**`cdn`（线上 CDN 地址）**
3. 用 `--put` 传 config → `/tmp/olz/config.json`
4. `cd /tmp/olz && nohup ./openlist server --config /tmp/olz/config.json > olz.log 2>&1 &`
5. **只留一个进程**：SO_REUSEPORT 会让多进程同时 LISTEN 同一端口，请求被随机分发，
   表现为「register 成功但 login 报 no administrator yet」这类假 bug。
   杀进程用 `kill -9 <pid>`（SIGTERM 无效），杀完用 `ps` + `netstat` 双重确认。

### 前端：Zig 版必须配线上 CDN
- Go 侧前端是 `//go:embed` 进 `public/dist` 的；`build_sqfs.yml` 的 CDN 版运行时
  **必须**配 `cdn` 字段（默认 `https://cdn.jsdelivr.net/npm/@openlist-frontend/openlist-frontend@latest/dist`，
  `WebVersion=rolling`，且**不要设 dist_dir**，否则 CDN 分支失效）。
- 用户的 Go 实例 config 里 `cdn=""`+`dist_dir=""`（它用的是内嵌 dist）；Zig 版没有
